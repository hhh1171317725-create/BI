# AI 分析规则

打开右下角数据助手，点击顶部「规则」。管理员可以维护全站共享规则，普通账号可以查看。规则保存后从下一次提问开始使用，旧回答保留原来的规则版本。保存规则本身不会发送 AI 请求。

- **文字规则**：直接填写分析重点、判断要求及回答顺序，例如「先讲现金利润和注册成本，再说明数据依据，最后给出建议」。
- **指标规则**：选择汇总、账户、任务、优化师或计划，设置最多 5 个同时满足的条件，再填写命中后的分析要求。例如账户的「消耗 > 200」且「预估 ROI < 1」，要求复核素材和转化质量。
- 可选择全部报表、大航海、京东日报或出价监测，启停及调整顺序。冲突时上方规则优先。新规则和示例默认停用，需要主动启用并保存。
- 支持最多 20 条规则，每条内容最多 2000 字，全部内容合计最多 12000 字。ROI 使用倍数，1 表示盈亏平衡；gap 使用比率，0.1 表示 10%；金额单位为元。

## 条件判断与数据范围

后端先检查指标条件，再把规则及实际命中证据传给已配置的 AI。回答标注规则版本，指标规则可以展开查看判断依据。无 AI 配置或请求失败时仍能看到后端的指标检查结果；自然语言分析要求不会被宣称已经执行。

日报使用 MySQL 中当前日期、账户及问题匹配范围的汇总。全部维度对象在前 80 条展示截断之前完成条件检查。大航海账户佣金与事件数仍按任务账户消耗占比分摊，依据中标注该口径。京东没有任务维度，日报没有广告计划维度。

出价监测使用浏览器当前筛选的全部汇总，以及最多 1000 个计划和每个其他维度最多 500 个对象。历史多日同计划先合并，收益指标遵守页面的价格匹配范围。超出数量上限会明确标注有限样本；未传入的对象不能视为未命中。

缺少指标、没有该维度数据、比率分母不为正数时显示无法判定。不会用有效订单代替结算数，不会用现金 ROI 代替普通 ROI。日报佣金与京东预估佣金合计、计费转化数等有对应别名时会注明实际指标来源。

## 保存与部署

`GET /api/pet/rules` 仅向已登录账号提供规则；`POST /api/pet/rules` 仅管理员可写。保存时带 `version`，其他管理员先保存后会返回 409，保留当前草稿并要求重新加载；提交超时提示结果未知，先刷新核对后才能再次保存。

配置原子写入 `DHH_RUNTIME_DIR/pet-analysis-rules.json`（默认 `.runtime/pet-analysis-rules.json`），服务重启后恢复，运行时使用不可变缓存快照。文件损坏会明确报错并保留原文件，不会悄悄清空配置。备份运行目录时应保留此文件。单个服务实例共享这份配置。

更新服务器：

```bash
cd /www/wwwroot/BI
sh scripts/deploy-server.sh
```

不需要数据库结构迁移。
