# 日报首屏与翻页优化

适用页面：大航海日报、京东广义新日报。本次只修改前端加载与数据复用方式，报表计算公式和接口不变。

## 首屏加载

原页面使用同步 script 标签下载 1,030,900 字节的 `echarts.min.js`，后续报表查询和初始化必须等待它完成。现在页面先启动报表查询，图表进入可视区域附近 160px 时才异步加载组件。

- 主图、下钻图共用一次加载请求；未查看图表时不必下载图表组件。
- 图表为空时显示“当前筛选暂无趋势数据”，不加载组件。
- 组件下载失败或超过 20 秒时，表格仍可查询和翻页，并提供“重试图表”。
- 下载期间变更筛选或下钻对象，完成后只绘制最新数据。
- 数据未变化时不重复 setOption，翻页不重绘趋势图。

组件下载大小为本地未压缩文件大小；线上传输可能经过压缩，实际端到端节省时间取决于网络及浏览器。

## 数据复用

排序和下钻筛选按数据数组与条件复用结果；刷新报表得到新数组后自然失效。每个源数组最多保留 12 个派生结果，使用 WeakMap 使过期源数据可被垃圾回收。中文排序复用 Intl.Collator，维持原有中文及数字排序行为。

后续代码应保持报表数组和行内容只读；原地修改数据时必须生成新数组才能使缓存失效。

## 验证

```sh
node --test scripts/daily-runtime.test.cjs
node scripts/daily-charts-ui-test.cjs
node scripts/daily-polish-ui-test.cjs
node scripts/daily-report-state-ui-test.cjs
```

- 10,000 行排序后连续复用 20 次，不再读取排序字段；新数组或排序条件变化时重新排序。
- 下钻选择、日期排序、条件隔离、缓存上限及原数组只读校验。
- 浏览器扣住图表脚本响应期间，表格可见且重新查询可完成。
- 实际 ECharts 渲染校验最新下钻对象和刷新后数值；翻页时 setOption 次数不增加；主图及下钻共用一次下载；失败后单独重试成功。
- 桌面及手机布局、日期筛选、查询失败恢复保持通过。

部署：`sh scripts/deploy-server.sh`，本次不需要数据库结构变更。
