# 报表加载与布局优化

## 查询链路

- 大航海、京东按原有日期、账户、视图、同步版本缓存结果。相同条件同时进入时，仅执行一次底表读取和聚合。达到容量时逐项淘汰最早结果，避免清空全部缓存。同步版本变化仍会重新查询，TTL 从计算完成后开始计时。
- 新增 `GET /api/bid-monitor/history/conversions?startDate=...&endDate=...`，沿用共享来源、登录及工具权限校验。仅投影历史赔付门槛需要的计划、双账户 ID、平台、转化数及日期，避免发送整份计划明细；不改变转化数计算范围和规则。
- 历史查询移除先 COUNT 再读取的双查询，采用 `LIMIT 200001` 与逐行读取。超过 200000 条仍拒绝并提示缩小范围，不返回截断的汇总。
- 含今日的区间并行读取归档和实时快照；两者成功后再合并，旧日期快照仍拒绝使用。用逐条追加替代展开运算，避免大数据量触发浏览器函数参数上限。

## 页面

出价监测筛选栏采用两行栅格：第一行搜索及业务筛选，第二行日期和操作按钮；中等宽度与手机单独适配。日报和出价表格使用等宽数字、稳定滚动条占位，日报维度标签支持横向滚动。

## 验证

- `./mvnw package`：233 项测试通过，包括同条件并发合并、同步版本更新和共享来源权限。
- `node scripts/bid-history-loading.test.cjs`：20 万条归档合并、并行请求、旧快照拒绝、精简历史转化的账户隔离与累计门槛。
- `node scripts/bid-monitor.test.cjs`：41 项计算口径测试。
- 出价监测、共享成员及大航海/京东页面交互测试通过，覆盖桌面和手机。

验证使用本地测试数据；尚未测量生产数据库查询耗时或真实网络延迟。部署需同步更新静态前端和后端 JAR，无需新增数据库字段或索引。
