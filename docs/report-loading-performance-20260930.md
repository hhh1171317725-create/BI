# 日报加载性能优化（2026-09-30）

## 改动

- JDBC 和报表累计值原本已是 Double，但公共数值函数仍逐次转字符串并重新解析。Double 现在直接读取并保留非有限数归零规则；字符串、Float、整数等其他输入继续使用原转换逻辑，避免改变原有精度行为。
- 京东分析接口增加可选 `view`：`by_optimizer`、`by_date`、`by_media`、`by_account`、`by_promoter`。仅计算并返回当前维度及其日期明细，汇总指标与全量口径一致。不传 `view` 时仍返回完整报表，兼容已有调用。
- 京东首屏只请求优化师维度。打开其他维度时再查询；同一筛选下切回已加载维度直接复用，减少网络传输、JSON 解析和服务器聚合。
- 维度查询使用已应用的筛选条件；修改筛选后重新查询会清除旧维度。后续查询发现同步版本变化时，也清除旧维度，避免不同版本混合。仅切换本地已加载维度不会主动检查服务端版本，需点击应用筛选重新查询以获取更新。
- 查询失败保留原表格和当前维度；数据同步期间禁止交叉发起查询。

## 本地测量

Windows / JDK 21，6,000 条模拟明细、15 天、400 个账户、40 位优化师。每项预热 3 次，取随后 5 次聚合加 JSON 序列化的中位数。

| 测量项 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 大航海优化师维度，聚合及序列化 | 214.29 ms | 102.92 ms |
| 京东完整报表，聚合及序列化 | 723.42 ms | 257.71 ms |
| 京东首屏：原完整报表 → 优化师维度 | 723.42 ms | 47.70 ms |
| 京东首屏未压缩 JSON | 6,033,238 字节 | 460,746 字节 |

这些是本地 CPU 和未压缩返回体测量，不包含 MySQL、网络、gzip 或浏览器耗时，不代表线上整体提速比例。首次打开未加载维度仍需请求接口和读取所选范围。没有新增原始明细内存缓存，也没有数据库迁移。

## 验证与复现

- 优化前后的大航海优化师报表与京东完整报表 JSON，去除下一次调度时间后逐字段一致。
- 京东五个按需维度分别与完整报表比对，含下钻明细、汇总和未知优化师过滤。
- 验证缓存隔离、同步版本失效、非法维度、旧 API 兼容及数值转换边界。
- 浏览器验证按需请求、已加载维度复用、修改筛选后的失效、同步版本变化、失败后保持原表格，以及桌面和手机布局。

```sh
./mvnw test -Dtest=DailyAnalysisBenchmarkTest -Dreport.benchmark=true -Dreport.benchmark.label=current
node scripts/daily-report-state-ui-test.cjs
node scripts/daily-polish-ui-test.cjs
```

基准测试默认跳过；显式运行后在 `.runtime/report-benchmark-*-metrics.json` 保存测量结果。标签为 `before` 的基准文件存在时，后续测量同时核对结果一致性。

部署需要同时更新后端 JAR 与前端：`sh scripts/deploy-server.sh`。
