# 出价监测：翻页与筛选渲染

本轮仅优化浏览器渲染，不修改任务识别、结算单价、gap、赔付和 ROI 公式，也不改变服务器接口查询范围。

- 汇总指标按 `filteredRows` 引用缓存。搜索、筛选、快照、任务价格和 gap 更新引起分析结果变化时，重新计算；单纯翻页复用结果。
- 单价覆盖信息按 `analyzed` 引用缓存，一次遍历完成缺失单价、手动单价、日报单价、同任务 gap 和 URL 识别数量统计。
- 任务选项只在分析数据或任务名称配置改变时重新收集；汇总列选项和表头只在内容改变时重建。
- 仅生成当前页行内容，生成一页前先确定展示列，避免逐行重复解析展示列配置。
- 中文输入法组合输入期间暂不筛选；完成选字后应用筛选。翻页回到表格顶端，横向滚动位置保留。
- 表头复用后，批量选择组件自行移除退出时的复选框，避免表头与行错位。
- 双月日历复用日期格式化器，每次绘制共用同一个当天日期，不逐格创建格式化器。

缓存依赖现有分析流程生成新数组；后续代码不应原地修改分析结果，否则需主动使缓存失效。

## 连续输入合并（2026-10-09）

出价监测关键词输入先前在每个字符后执行整套筛选、汇总、排序与 DOM 更新。如今只在连续输入停顿 140 ms 后执行一次；Enter 立即匹配。空搜索、原生清空、清空关键词按钮、任务/优化师/平台等离散筛选仍立即更新。

输入框显示匹配中的提示，并提供一键清空。中文输入法开始选字时撤销之前的待处理输入，组合期间不筛选；完成选字后再匹配。任何其他即时渲染会撤销待处理计时，防止较早的回调重复更新结果。

导出和完整报表上下文读取先应用待处理关键词，再读取数据；新关键词无结果时禁用导出，不会下载上次结果。跳页使用最新匹配行数，待处理搜索期间点击前后页先显示新结果第一页。表格名称点击保持当前 DOM 与当前 `visible` 行的一致性，没有增加全局点击或失焦自动刷新。

新增的调度器使用普通计时器，没有第三方依赖，也不改变收益、预警公式或服务端查询范围。搜索仍只使用已加载数据；原有共享快照和日报版本轮询继续独立运行。

```sh
node --test scripts/bid-performance.test.cjs scripts/bid-refresh-state.test.cjs scripts/bid-monitor.test.cjs
node scripts/bid-monitor-ui-test.cjs
node scripts/bid-filter-input.test.cjs
node scripts/bid-filter-input-ui-test.cjs
node scripts/bid-shared-ui-test.cjs
```

测试包含 10,000 条模拟计划：首次读取后连续 20 次复用汇总与覆盖统计，不再读取计划价格字段；改变数组后重新统计。浏览器测试验证翻页复用表头和指标节点、筛选和 gap 更新后数据变化、中文输入、多维汇总、批量导出、预警与历史查询。此为重复计算次数的验证，不代表线上接口响应速度或固定百分比的整体提速。

连续输入测试在 3,000 条模拟计划上确认：20 次快速输入只执行 1 次最终渲染，同时覆盖计时器失效、IME、Enter、清空、即时导出、空结果导出、离散筛选、跳页、助手上下文以及手机布局。这是本地交互与重复工作量验证，不是线上接口耗时测量。
