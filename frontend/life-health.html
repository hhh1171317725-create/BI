AI 个人生活管理

Personal Life · 独立健康数据空间

查看睡眠与运动趋势，按需授权生活助手分析。独立登录、独立数据库，不与 BI 广告业务混用。

先部署，再连接手机

这个页面是入口，不是健康服务本身。首次使用按下面三步完成配置；已部署的用户直接填写地址即可。

① 首次部署 · 展开服务器操作

在宝塔为健康服务新建独立子域名，例如 health.huanghaha.fun，解析到服务器并申请 HTTPS 证书。这个示例地址不会自动创建，也不会自动修改 BI 站点。

服务器需安装 Docker 与 Compose v2。以下命令初始化一个新服务，不覆盖已有 .env，不重启现有 Java：

cd /www/wwwroot/BI
git pull --ff-only origin main
cd personal-life
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/work" -w /work node:24-bookworm-slim node scripts/configure.mjs https://health.huanghaha.fun
docker compose config --quiet
docker compose up -d --build
docker compose ps

如使用其他域名，替换上述域名。已有 .env 时跳过初始化命令，在服务器私有编辑器中核对 APP_ORIGIN。

新健康站点反向代理到 http://127.0.0.1:3100，HTTPS 转发头、上传限制及日志配置见仓库 personal-life/deploy/nginx.conf.example。数据库不开放公网端口。

初始化会生成强密码和独立上传密钥，仅写入服务器 personal-life/.env，不在网页或日志中显示。证书、DNS 和服务器启动完成前，不要在手机开启上传。

这里只保存服务域名，不保存任何密码或密钥。打开工作台后使用 .env 中的独立账号密码登录。

③ Hozz 手机自动同步

Automatic → Add a destination → Web address。

Web address：填写上面的已部署地址后，这里显示接收接口

Authorization header：Bearer 你的INGEST_API_KEY，Bearer 后有一个空格。请从服务器私有配置复制到手机，不要发到聊天或截图。

Format 选 JSON，How often 选 When new data arrives。首次从 7 天前开始；若有请求大小限制，选 1 MB。先测试连接，再同步。

实际睡眠阶段会转换为时长，卧床不算睡眠；重复上传不会重复累计。iOS 后台调度与锁屏会延迟同步，不保证实时。

自动同步

支持 Hozz JSON v1；安全留存、去重、更新与删除、历史补传。

睡眠分析

7/30 天趋势、入睡与起床时间、实际睡眠区间与规律性。

运动分析

步数、运动次数与时长、活动热量和体重趋势。

私人 AI 助手

只发送授权的必要摘要；没有数据不编造，不作为医学诊断。

未支持的类型或版本只留存原始数据，页面会提示；不会把未知数据当作指标。
